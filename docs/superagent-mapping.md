# Super-agent 那篇文章 vs Stoa：哪条能搬，哪条不该搬

对照对象：DeepSeek Harness 团队《Super-agent 设计探索：迈向更自主的 Agent 系统》（2026-10-31）
＋ 开源原型 `deepseek-ai/dsh-superagent-prototype`（MIT，research prototype）。
本文只回答一个问题：**一个单用户桌面工具，能从里面拿走什么。**

## 一句话判断

文章的五个模块都在解决「多会话、多任务、多人协作」的规模问题。
Stoa 是一个人、一台机器、一个会话，**规模带来的问题一个都不存在**；
但文章里有两块是「规模无关」的工程方法——**确定性准入**和**用代码盯进展**——这两块可以直接搬，而且我们已经在搬。

## 逐模块对照

| 文章模块 | 它解决的问题 | Stoa 现状 | 判定 |
|---|---|---|---|
| Router / Worker 双层 | 跨信道的连续 + 多任务并发 | 单会话，`session` 只是历史分段 | **不适用**。用户只有一个人、一个窗口；拆层只会增加延迟和上下文割裂 |
| 事件驱动（Trigger） | 不用人发指令也能推进 | 有 `cron`（`0 13 * * 1-5` 报告）+ 提醒 + 自选股，但没有事件准入表 | **部分适用**。定时驱动有了，缺「什么事件值得叫醒模型」的确定性规则 |
| Fast / Slow Path 两级过滤 | 高噪音、低触发率 | `auto_skip()`、`answercheck`、`guards` 都是「代码先筛，模型后判」 | **已经在做**，思路一致。可以补的是把「跳过原因」显式记下来（已做，见 `reviews` 表） |
| 订阅直通 | 后续事件不再经过全局节点 | 无多会话，无此问题 | **不适用** |
| Inline & Spill | 窗口预算管理 | 工具描述 448→97 tokens、`context.clip_tool` 按预算收缩、结果留 `_cite` | **已经在做**。文章给的框架更完整：ID+摘要 → 按局部性内联 → 超预算溢出留续读入口 |
| 异步 ReAct Loop（start/stop） | 后台工具阻塞前台对话 | 同步 `run_tool`，一问一答 | **适用但成本高**。需要把工具层改成任务化 + 结果作为事件投回，属于产品级改造 |
| 存算分离 / 端侧 daemon | 设备休眠即停 | 本地单体，无云端 | **不适用** |
| Watchdog（外部 Control Loop） | 长跑任务跑偏、无效循环、进程活着但没进展 | 只有「复盘」（事后学习），**没有「进行中是否在打转」的判断** | **最该搬**，已在 PR 里落地：`guards` 规则 7 |

## 搬了什么

`stock_agent/guards.py` 规则 7：同一工具、同一参数、结果一字不差地调两次，**第三次直接拦下**，返回的不是同一份结果，而是一句「你已经问过三次，结果一样，换参数或说明卡在哪」。

三条设计取舍，都是文章点出来的：

1. **放在代码里，不放在提示词里。** 文章说 Watchdog 要在主系统之外；我们没有外部进程，但同样把它做成确定性规则——模型陷入循环时，提示词救不回来。
2. **以「结果有没有变化」为判据。** 参数相同但结果在变（盯行情轮询）不算打转，计数清零。这是文章的「实质进展」在单机上的可测形式。
3. **缓存命中也得拦。** Stoa 原本对参数相同的只读调用直接复用缓存结果，模型会拿到一模一样的数据却毫无提示——这正是需要被看见的「静默打转」。现在这条路径也会走拦截。

## 不搬的理由，写清楚

- **Router/Worker**：文章自己也说，双层架构的代价是 Router 要维持全局记忆；我们只有一个用户，全局记忆就是会话本身。
- **存算分离**：桌面工具的价值恰恰是「数据不出本机」，上云的收益（持久在线）对单人场景不成立。
- **异步 ReAct**：文章的动机是「人在等」，Stoa 的耗时工具（`deep_analysis`）已经有事件流式回报；改成任务化会牵动 `ledger` 断点续跑与引用编号，收益不抵风险。

## 文章承认没解决的（我们同样没有）

- 跨月的长程记忆：文章靠引用图链式召回，只能解决「近期」。
  Stoa 的对应问题是技能没有时间归属——已在本仓库加 `learned` + `as_of`（PR #15），但记忆与判断条目仍无逐条日期。
- 上下文边界与 A2A：一人一机时不成立。
- 安全与隐私：事件驱动越广，不可信输入越多；Stoa 的做法是 `taint` 标记 + 注入闸门，比文章更保守，也更适合桌面场景。
